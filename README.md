# Desktop Pet

一个基于 Live2D 的 AI 桌宠。角色由大语言模型驱动对话，回复会被实时合成语音朗读出来，并根据情绪切换表情与动作，同时用口型同步让模型"开口说话"。

> 前端基于 Vue 3 + Vite，通过 [Tauri 2](https://tauri.app/) 以桌面应用形式运行；开发调试时也可以直接在浏览器中打开。

## 功能

- **Live2D 渲染**：基于 `pixi.js` + `pixi-live2d-display`（Cubism 4），支持待机动作、眨眼、呼吸、物理摆动，透明背景。
- **交互**：视线跟随鼠标（空闲时自动扫视）、拖拽移动、滚轮缩放、点击命中区域触发动作。
- **AI 对话**：流式输出，多会话管理（新建 / 切换 / 删除），会话记录保存在本地。
- **语音合成**：回复按句切分后逐句合成并按顺序播放，播放音量可调。
- **情绪表达**：模型在回复中输出方括号括起来的情绪标签（如 `[happy]`、`[laughs]`、`[short pause]`），前端据此随机播放带有对应标签的表情或动作；支持标签的语音合成（Fish Audio、ElevenLabs v3 / v4）还会据此调整语气、发出笑声或停顿，其他服务商合成前去掉标签。
- **口型同步**：实时分析播放音频的音量，驱动模型嘴部开合。
- **Agent（技能 + 工具调用）**：先由 LLM 识别用户意图，需要时调用技能中的工具完成请求，再以角色口吻润色结果；内置日期时间、天气、划词助手、图片理解、看屏幕、记忆管理、待办、本地文件、Office 文档、网页搜索、运行脚本十一个技能，提醒到时桌宠会主动开口。
- **划词**：在任意应用中选中文字后按下快捷键，即可翻译、解释、总结、润色或分析代码。
- **图片理解**：发送图片或截图，即可解释图片内容、提取或翻译图中文字、分析报错。
- **待办与提醒**：用自然语言创建、查询、修改待办或设置提醒（如「明天下午三点交周报，提前半小时提醒我」「十分钟后提醒我喝水」），支持优先级、标签、重复与提醒，到时桌宠主动开口；也可以在待办面板中直接管理。
- **本地文件**：在授权的文件夹中查找文件、阅读文件内容（文本、代码、Word、PowerPoint、PDF、Excel），新建或修改文本文件，按类型或月份整理文件夹；写入与移动前都需要确认，并且可以撤销，不会删除文件。
- **Office 文档**：新建或修改 Word、Excel、PowerPoint 文件并导出 PDF：由 LLM 写一段代码，经你同意后通过本机的 Microsoft Office（优先）或 Python 库完成；修改前自动备份，可以撤销。
- **网页搜索**：搜索互联网并阅读网页原文，综合多个来源回答并附上链接。
- **运行脚本**：运行授权文件夹中的 Python、JavaScript、PowerShell、批处理、Shell 脚本，或直接运行一段临时的代码，并查看输出；每次运行前都会展示命令与完整代码，经你同意后才会运行。
- **长期记忆**：每轮对话后由 LLM 提取值得记住的信息，与已有记忆去重、合并后分类存储在本地 SQLite 中；每次回复前按语义相关性、重要程度、新近程度综合排名，把最相关的记忆写入 Prompt。
- **人物设定**：可自定义角色的名字、性格、背景故事与说话风格，并在多个人设之间切换。
- **桌面窗口**：无边框、透明背景、始终置顶，不占用任务栏；透明区域鼠标穿透，不影响操作其他应用；通过托盘图标控制。
- **可配置**：所有设置均可在应用内的设置面板修改，并持久化到 `localStorage`。

## 快速开始

环境要求：

- Node.js `^20.19.0` 或 `>=22.12.0`，推荐使用 [pnpm](https://pnpm.io/)
- 以桌面应用运行时还需要 [Rust](https://www.rust-lang.org/tools/install)（`1.90` 及以上）以及 Tauri 的[系统依赖](https://tauri.app/start/prerequisites/)（Windows 上为 WebView2，Windows 10/11 通常已自带）

```sh
pnpm install
```

**以桌面应用运行**（会自动启动 Vite 开发服务器，首次运行需要编译 Rust 依赖，耗时较长）：

```sh
pnpm exec tauri dev
```

**在浏览器中运行**（仅前端，不含鼠标穿透、托盘等桌面功能）：

```sh
pnpm dev
```

启动后：

1. 点击右下角的 ⚙️ 打开设置面板，在 **Provider** 页填写 LLM 与 TTS 服务的 API Key，并选择要使用的模型（及声线）。
2. 点击 💬 打开对话面板，开始聊天。
3. （可选）在 **Tools** 页配置网页搜索服务，调整允许桌宠访问的文件夹。

> 页面通过 CDN 加载 Live2D Cubism Core（见 [index.html](index.html)），首次运行需要能访问 `cubism.live2d.com`。

## 桌面窗口

桌宠窗口铺满当前显示器的工作区（不遮挡任务栏），背景完全透明，看起来就像模型直接站在桌面上。

- **鼠标穿透**：鼠标位于透明区域时，点击会落到下方的其他应用上；只有位于模型的不透明像素或设置 / 对话面板上时，才由桌宠响应。按住鼠标拖拽期间不会切换为穿透。
- **全局视线跟随**：模型的视线会跟随整个桌面上的鼠标，而不仅限于窗口内。
- **托盘图标**：窗口不在任务栏显示，通过托盘图标操作。左键单击显示 / 隐藏桌宠，右键菜单提供：
  - 显示 / 隐藏
  - 始终置顶（开关）
  - 重置窗口位置
  - 退出
- 打包后的版本会屏蔽 WebView 自带的右键菜单，开发模式下保留以便调试。

> 实现方式：开启穿透后网页收不到鼠标事件，因此前端（[desktop.ts](src/composables/desktop.ts)）会定时轮询全局鼠标坐标，结合 `elementFromPoint` 与 Live2D 画布的像素采样判断当前位置是否需要响应，再调用 `setIgnoreCursorEvents` 切换穿透状态。需要参与这一判断的透明容器以 `data-passthrough` 属性标记。

### 接入本地 IndexTTS

IndexTTS Provider 默认地址为 `http://localhost:8000/v1`，服务端需要提供以下接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/models` | 校验连接、获取模型列表（`{ data: [{ id }] }`） |
| `POST` | `/audio/speech` | OpenAI 兼容的语音合成接口，输出 wav |
| `GET` | `/audio/voices` | 获取音色列表（`{ voices: [{ id, name }] }`） |
| `POST` | `/audio/voices` | 上传音色参考音频（`multipart/form-data`：`name`、`file`、`overwrite`） |
| `DELETE` | `/audio/voices/:id` | 删除音色 |

## 添加 Live2D 模型

1. 将模型文件放到 `public/assets/live2d/models/<模型名>/` 下。
2. 在设置面板的 **Live2D** 页添加模型，填写 `.model3.json` 的路径（如 `/assets/live2d/models/<模型名>/model.model3.json`）。

要让模型响应情绪，需要在 `.model3.json` 的动作与表情条目上添加自定义的 `Tags` 字段：

```json
{
  "File": "Motions_hair_0.json",
  "Tags": ["happy", "cheerful", "shy", "playful"]
}
```

`Tags` 中填写情绪标签的名称（不带方括号，完整词表见 [emotion-tags.ts](src/utils/emotion-tags.ts)），如 `happy`、`giggles`、`clears throat`：模型输出 `[giggles]` 时，随机播放一个带有 `giggles` 标签的表情或动作。另外，带有 `thinking` 标签的表情会在等待模型回复时播放。

## Agent

每条用户消息会经过三个阶段（[src/agent/](src/agent/)）：

1. **意图识别**（[router.ts](src/agent/router.ts)）：LLM 只看到各技能的名称、描述与示例，输出 `{"skills": [...], "reason": "..."}`。不需要技能（闲聊）时直接进入第 3 步；识别失败也会退化为普通对话。
2. **工具执行**（[executor.ts](src/agent/executor.ts)）：只把被选中技能的使用说明和工具交给 LLM，由它自主调用工具（最多 10 轮），并客观总结执行结果。其他可用的技能只列出名称与简介：执行中发现还需要它们时（例如用户把要求写在截图里，读出图片内容后才知道要写 Word 文档），LLM 调用 `load_skills` 按需加载，之后的步骤就能使用这些技能的说明与工具。模型不一定会意识到图片中的文字是要它完成的任务，因此这一轮只用了图片理解时，还会带着读出的图片内容再识别一次意图（[router.ts](src/agent/router.ts) 的 `routeImageRequest`），需要其他技能时继续执行；只是想看懂图片，或者图中的指令明显不是写给桌宠的（如网页、聊天记录中的内容）时，到此为止。工具抛出的错误、参数校验失败都会被记录下来，而不是中断流程。这一阶段使用流式输出：模型思考、编写较长的工具参数（如一段 Office 脚本）时，界面上会显示「思考中」「已写 N 字」等进度；输出超过模型单次输出的长度上限、工具调用没写完时，会提醒模型精简（用数组加循环生成、分几次完成）后重试一次。
3. **角色润色**（[chat.ts](src/stores/chat.ts)）：执行记录被附加到人设提示词之后，由 LLM 以角色的口吻、带情绪标签流式回复，后续照常进入语音合成与表情动作流程。

三个阶段使用同一个 LLM Provider。启用 Agent 后每条消息会多一次意图识别请求，可以在设置面板的 **Skills** 页关闭 Agent 或单独禁用某个技能。

意图已经明确时（如点击划词 / 截图工具栏上的按钮），会通过 `directCall` 跳过前两个阶段的 LLM，直接调用对应的工具，再由角色润色。

| 技能 | 工具 | 说明 |
| --- | --- | --- |
| 日期时间 `datetime` | `get_current_time`、`days_between`、`shift_date` | 当前时间、日期间隔、日期推算 |
| 天气 `weather` | `get_weather` | 使用 [Open-Meteo](https://open-meteo.com/) 免费接口，无需 API Key |
| 划词助手 `selection` | `translate_text`、`explain_text`、`summarize_text`、`polish_text`、`analyze_code` | 处理划词选中或直接发来的文字，结果以卡片形式完整展示，见下文「划词」 |
| 图片理解 `image` | `describe_image`、`extract_image_text`、`translate_image`、`analyze_error` | 解释图片、看图答疑、提取 / 翻译图中文字、分析报错截图，见下文「图片理解」 |
| 看屏幕 `screen` | `look_at_screen` | 由 LLM 判断是否需要看屏幕，经用户授权后截取当前窗口交给识图模型分析，见下文「看屏幕」 |
| 记忆管理 `memory` | `list_memories`、`search_memories`、`forget_memories` | 用户问「你都记得我什么」或要求「把这件事忘了」时查看、忘掉记忆（忘掉前请用户确认），见下文「记忆管理」 |
| 待办 `tasks` | `create_task`、`list_tasks`、`update_task`、`complete_task`、`delete_tasks` | 创建、查询、修改、完成待办，设置定时提醒，重复任务自动生成下一次；删除前请用户确认，见下文「待办与提醒」 |
| 本地文件 `files` | `search_files`、`list_folder`、`read_file`、`write_file`、`edit_file`、`organize_folder`、`move_files`、`create_folder`、`reveal_file` | 在授权的文件夹中查找、阅读（包括 Office 文件与 PDF）、新建与修改文本文件、整理文件；写入与移动前请用户确认，可以撤销，见下文「本地文件」 |
| Office 文档 `office` | `run_office_script`（与「本地文件」共用 `read_file`、`reveal_file`） | 运行代码新建或修改 Word、Excel、PowerPoint，优先调用 Microsoft Office，其次使用 Python 库；运行前请用户同意并备份，可以撤销，见下文「Office 文档」 |
| 网页搜索 `web` | `web_search`、`read_webpage` | 搜索互联网，阅读网页原文后回答并注明来源，见下文「网页搜索」 |
| 运行脚本 `scripts` | `run_script`、`run_code` | 运行授权文件夹中的脚本，或直接运行一段临时的代码，并返回输出；每次运行前都请用户同意，见下文「运行脚本」 |

### 划词

在任意应用中选中文字，按下划词快捷键（默认 `Ctrl + Alt + Q`，可在设置面板的 **Skills** 页修改），鼠标旁会弹出工具栏：

- **翻译 / 解释 / 总结 / 润色 / 代码**：打开对话面板并直接执行，完整结果显示在卡片中（可一键复制），桌宠只用一两句话点评，不会把全文朗读一遍。选中的内容像代码时会突出「代码」按钮。
- **提问**：把选中的文字附加到输入框上方，由你输入具体问题。
- 之后可以继续追问，如「再翻译成日语」「第二点展开说说」，工具会从对话中找回最近一次划词的原文。

实现方式（[capture.rs](src-tauri/src/capture.rs)）：快捷键触发后等待修饰键松开，备份剪贴板，模拟一次 `Ctrl + C`（macOS 为 `Cmd + C`），读取新的剪贴板文字后再恢复原有内容。注意：

- 剪贴板只能恢复文本和图片，原有的文件、富文本等其他格式会丢失；Windows 的剪贴板历史（`Win + V`）中会留下划词的内容。
- 不建议只用 `Alt` 作修饰键：部分应用在松开 `Alt` 时会激活菜单栏，导致复制失败。
- 管理员权限运行的程序不接受普通程序模拟的按键，无法从中划词。macOS 需要在系统设置中授予辅助功能权限。
- 选中的是图片（如浏览器中的图片）时，复制到的图片会交给「图片理解」技能处理。

### 图片理解

发送图片的方式：

- **截图快捷键**（默认 `Ctrl + Alt + W`）：调起系统截图工具框选屏幕区域，鼠标旁会弹出工具栏，可以直接 **解释 / 提取文字 / 翻译 / 分析报错**，或点击 **提问** 把截图附加到输入框。
- 在对话面板中 **粘贴**（如 `Win + Shift + S` 截图后直接 `Ctrl + V`）、**拖入** 图片文件，或点击输入框左侧的按钮选择图片、截图。一条消息最多 4 张图片，可以只发图片不写文字。

处理方式：

- 图片本身不会发给对话模型，消息中只带有 `【附图：图片 id】` 标记；图片理解技能的工具根据标记读取图片，交给 **识图模型** 处理，结果以卡片形式展示，再由角色点评。因此对话模型不支持图片也没关系。
- 识图模型默认跟随对话模型。对话模型不支持图片输入时（如 DeepSeek），在设置面板的 **Skills** 页为图片理解单独指定一个支持视觉的模型（如 GPT-4o、Claude、Gemini）。
- 之后可以继续追问，如「第二步具体怎么做」「把图里的文字翻译成日语」，工具默认处理最近一次发送的图片。
- 图片保存在 IndexedDB 中（`localStorage` 容量太小），删除会话或清空对话时一并删除。尺寸过大（最长边超过 2048 像素或超过 2MB）的图片会被缩小并转为 JPEG。
- 截图在 Windows 上使用系统自带的「截图工具」（`ms-screenclip:`），需要开启截图工具的「自动复制到剪贴板」（默认开启）；macOS 使用 `screencapture`；其他系统暂不支持截图，可以直接粘贴图片。

### 看屏幕

用户问「我现在这个程序为什么运行不了？」这类需要看到屏幕才能回答、但又没有附上文字或截图的问题时，LLM 会自己决定调用 `look_at_screen`：

1. **意图识别** 选中「看屏幕」技能，**工具执行** 阶段的 LLM 给出看屏幕的理由（`reason`）与要弄清的问题（`question`）。
2. 找到用户 **最近使用的窗口**。用户在对话面板里打字时，前台窗口其实是桌宠自己，因此 Rust 端（[screen.rs](src-tauri/src/screen.rs)）会在后台持续记录最近一个不属于桌宠的前台窗口作为目标。
3. 对话中弹出 **授权卡片**，显示理由与窗口标题，可以选择「拒绝 / 允许这一次 / 始终允许」。2 分钟无人回应视为拒绝；拒绝后桌宠会建议改为发送报错文字或截图。
4. 允许后只截取 **这一个窗口**（使用 `PrintWindow`，不会截到桌宠和其他窗口），截图附加到这条用户消息上（对话中可见，之后可以继续追问），再交给识图模型分析，结果以「屏幕分析」卡片展示。

「始终允许」可以在设置面板 **Skills → 授权** 中撤销。截取窗口目前支持 Windows 与 macOS（macOS 需要授予屏幕录制权限）；最小化的窗口无法截取。

### 待办与提醒

在对话中用自然语言管理待办（[tasks.ts](src/agent/skills/tasks.ts)），如「帮我记一下明天下午三点交周报，提前半小时提醒我」「十分钟后提醒我喝水」「我今天还有什么要做的」「把交周报改到周五」「周报写完了」「每周一提醒我开例会」。LLM 先把「明天下午三点」这类说法换算成具体时间，再调用工具；时间无法识别或提醒时间已经过去时，工具会报错并让 LLM 修正。

- 每个任务可以有备注、截止时间（可以只有日期）、优先级（低 / 普通 / 高）、标签、重复（每天 / 工作日 / 每周 / 每月）与提醒时间。
- 提醒统一由待办管理：「十分钟后提醒我喝水」这样的单纯提醒也是一个只带提醒时间的任务。到了提醒时间桌宠主动开口，应用关闭期间错过的提醒会在下次启动时补发；任务完成、删除或清除提醒时间时，提醒随之取消。以前单独设置的提醒会自动转为待办任务。
- 完成重复任务时自动生成下一次，截止时间与提醒时间一起顺延（每月 31 日的任务遇到小月时取月末）。
- 删除任务前会弹出授权卡片，列出要删除的任务。

点击右下角的 ☑ 打开 **待办面板**（可拖动）：在顶部快速添加；按「待办 / 今天 / 逾期 / 本周 / 已完成」查看；勾选完成，取消勾选恢复；双击任务或点击编辑按钮修改；可以一键清除已完成的任务。按钮上的数字是未完成的任务数，有逾期任务时变为红色。待办保存在 `localStorage` 中。

### 本地文件

「本地文件」技能（[files.ts](src/agent/skills/files.ts)、[src-tauri/src/files/](src-tauri/src/files/)）只能访问 **授权的文件夹** 及其子文件夹。第一次使用时会自动授权桌面、文档、下载、图片，可以在设置面板的 **Tools → 文件访问** 中取消授权或添加其他文件夹（不能授权磁盘根目录与系统目录）。对话中说「下载」「桌面/报告」时，会被解析为对应的授权文件夹。

- **查找**：按文件名关键词、扩展名、修改时间（如「上周」）、文件内容查找，结果按修改时间从新到旧排列。会跳过隐藏文件与 `node_modules`、`.git` 等目录，单次最多扫描 5 万项、耗时 5 秒。
- **阅读**：支持纯文本与代码文件（自动识别 UTF-8 / UTF-16 / GBK 编码）、Word（`.docx`）、PowerPoint（`.pptx`，按页列出）、PDF（按页列出，使用 [pdf-extract](https://github.com/jrmuizel/pdf-extract)）与表格（`.xlsx` / `.xls` / `.xlsb` / `.ods`，使用 [calamine](https://github.com/tafia/calamine)），最多读取前 12000 字。表格按工作表列出，第一行是列字母，每行开头是行号（每个工作表最多 1000 行、50 列），便于按「B3」这样的位置修改；公式显示计算结果。扫描件 PDF 没有文字，读不出内容（可以截图后交给「图片理解」）；暂不支持旧版的 `.doc` / `.ppt`。
- **整理**：把文件夹第一层的文件按 **类型**（图片 / 文档 / 表格 / 演示文稿 / 压缩包 / 音频 / 视频 / 安装程序 / 代码 / 电子书 / 字体 / 其他）、**月份**（按修改时间，如 `2026-11`）或 **扩展名** 归入子文件夹，快捷方式与隐藏文件保持不动。也可以按要求移动、重命名指定的文件，或新建文件夹。
- **新建与修改**（[write.rs](src-tauri/src/files/write.rs)）：`write_file` 新建文件（所在文件夹不存在时自动创建），文件已存在时默认不覆盖；`edit_file` 修改已有文件——把文件中的一段原文替换为新内容（原文必须与文件内容完全一致，并且只出现一次，避免改错位置），或在末尾追加内容。修改时保持原文件的编码（UTF-8、UTF-8 BOM、UTF-16、GBK）与换行符（CRLF / LF）。纯文本类文件（txt、md、csv、json、yaml、html、代码等）最大 4 MB。可以写入脚本（`.py`、`.js`、`.ps1`、`.bat`、`.cmd`、`.sh`），新建时自动使用解释器需要的格式：批处理用系统编码（中文 Windows 上为 GBK）与 CRLF 换行，内容中有系统编码无法表示的字符（如 emoji）时会报错；PowerShell 用带 BOM 的 UTF-8（否则 Windows PowerShell 5.1 读取中文会乱码）；Shell 用 UTF-8 与 LF 换行。Word、Excel、PowerPoint 文件由「Office 文档」技能新建与修改；不能写入 PDF，以及隐藏的文件或文件夹（如 `.git` 中的文件）；不能把文件内容清空。
- **确认与撤销**：写入与移动前一定会弹出授权卡片，每次都需要确认（没有「始终允许」）：移动时列出完整的移动计划；写入时显示改动预览（`-` 为删除的行，`+` 为新增的行，并标出行号）。写入时会校验文件在确认期间没有被改动过，否则不写入。移动时重名会自动加上「 (1)」这样的编号，不会覆盖已有文件。所有操作记录在 **Tools → 文件操作记录** 中（最近 20 次），可以一键撤销：移动的文件移回原处；修改前的原文件备份在应用数据目录的 `file-backups` 中（最近 50 份），撤销时恢复原内容；新建的文件撤销时删除。「Office 文档」技能通过脚本改动的文件也记录在这里。文件在之后又被改动过时不会撤销，避免丢失之后的修改。
- **在文件夹中显示**：在资源管理器中选中找到的文件，由用户自己打开。

为了安全，技能不提供删除、打开或运行文件的工具（唯一会删除文件的情况是你在设置中撤销「新建文件」，且只删除桌宠新建、之后没有被改动过的那个文件）；Rust 端在每次调用时都会把路径规范化，重新检查它是否位于授权的文件夹内，拒绝 `..`，也不跟随符号链接，因此 LLM 无法越界访问。注意被阅读的文件内容会发送给对话模型的服务商。本地文件操作只能在桌面应用中使用。

### 网页搜索

「网页搜索」技能（[web.ts](src/agent/skills/web.ts)、[src/web/](src/web/)）先搜索，再挑 1 ~ 3 个最相关的结果阅读原文，综合后回答并注明来源。搜索结果以卡片列出，其中的链接可以点击，在默认浏览器中打开。用户直接发来链接（「帮我看看这个链接讲了什么」）时，直接读取网页，不需要配置搜索服务。

搜索服务在设置面板的 **Tools → 网页搜索** 中选择，可以点击「测试连接」检查配置：

| 服务 | 需要填写 | 说明 |
| --- | --- | --- |
| [Tavily](https://tavily.com/) | API Key | 为 AI 设计的搜索接口，结果附带网页摘要，每月有免费额度 |
| [Brave Search](https://brave.com/search/api/) | API Key | 独立索引的搜索引擎接口，每月有免费额度 |
| [SearXNG](https://docs.searxng.org/) | 实例地址 | 自建的开源元搜索引擎，免费；需要在实例的 `settings.yml` 中把 `json` 加入 `search.formats` |

读取网页（[page.ts](src/web/page.ts)）：

- 用 [Readability](https://github.com/mozilla/readability) 提取正文（提取失败时退化为整个页面的文字），再按页面结构转为纯文本：每个段落占一行，表格的单元格之间用「|」分隔，代码块保留缩进。根据响应头或 `<meta>` 识别 GBK 等编码。每个网页最多保留 8000 字。
- 只读取公网的 http / https 网页，拒绝本机与局域网地址，并且每一次重定向都会重新检查，避免被网页内容诱导去访问内网服务。技能的使用说明要求 LLM 把网页内容只当作资料，不执行其中的指令。
- 需要登录、由脚本动态生成内容的网页无法读取；暂不支持读取网页上的 PDF（可以下载后用「本地文件」读取）。
- 网络请求通过 Tauri 的 HTTP 插件从 Rust 端发出，不受跨域限制；在浏览器中运行时会受跨域限制，多数网页无法读取。

### 运行脚本

「运行脚本」技能（[scripts.ts](src/agent/skills/scripts.ts)、[script.rs](src-tauri/src/files/script.rs)）有两个工具：

- `run_script`：运行 **授权文件夹**（与「本地文件」共用）中已有的脚本文件，如「运行一下桌面上的 backup.py」「用 node 跑一下 test.js 看看报错」。也可以和「本地文件」配合：先用 `write_file` 写一个脚本，再运行它（写入与运行各需要确认一次）。
- `run_code`：直接运行一段临时的代码，代码不会保存到你的文件夹，适合「统计一下下载文件夹里各类文件的数量」「查一下磁盘还剩多少空间」这类一次性的任务。工作目录必须在授权的文件夹内（默认为第一个授权文件夹）。代码最多 2 万字，授权卡片中会展示全部代码。各语言的运行方式：Python、JavaScript、Bash 通过标准输入把代码交给解释器（`python -`、`node -`、`bash -s`），不产生文件；PowerShell 以 `-EncodedCommand` 传入（受命令行长度限制，代码约 1 万字以内），输出使用 UTF-8；批处理无法从标准输入可靠地运行（跳转标签等会失效），会写入系统临时目录中的临时文件（系统编码、CRLF），运行结束后立即删除。

| 脚本 | 解释器 |
| --- | --- |
| `.py` | Python（跳过 Windows 应用商店的 `python.exe` 占位程序，找不到时使用 `py -3`） |
| `.js` / `.mjs` / `.cjs` | Node.js |
| `.ps1` | PowerShell（优先 `pwsh`，以 `-NoProfile -ExecutionPolicy Bypass -File` 运行） |
| `.bat` / `.cmd` | cmd（仅 Windows） |
| `.sh` | Bash（Windows 上使用 Git for Windows 的 Bash，不会用到 WSL） |

- **每次运行都需要同意**：运行前对话中会弹出授权卡片，列出完整的命令、工作目录、最长运行时间与脚本内容（直接运行的代码会完整展示），并提醒脚本会以你的身份运行、产生的改动无法撤销。没有「始终允许」，用户拒绝时不会运行。
- **范围**：不能运行 exe 等程序；脚本与工作目录都必须在授权的文件夹内（每次运行时由 Rust 端重新校验）。注意代码运行后拥有你的全部权限，工作目录的限制只决定代码从哪里开始运行，并不能阻止代码访问其他位置，所以请在授权卡片中看清代码再允许。
- **参数**：逐个直接传给解释器，不经过 shell 拼接，避免命令注入。工作目录默认为脚本所在的文件夹。
- **运行环境**：标准输入关闭（脚本等待输入时不会卡住，需要的值请通过参数传入）；Windows 上不弹出控制台窗口；Python 以 UTF-8 输出。
- **超时与停止**：默认最多运行 60 秒，可以指定到 600 秒；超时或在对话中停止生成时，会结束脚本及它启动的所有子进程。
- **输出**：同时收集标准输出与错误输出，自动识别 UTF-8 / GBK 编码；过长时保留开头与结尾。结果以卡片展示（退出码、用时、输出），再由角色说明是否成功、分析错误原因。
- **设置**：**Tools → 运行脚本** 中显示本机找到的解释器与最近 30 次运行记录；不需要这个技能时可以在 **Skills** 页禁用。

### Office 文档

「Office 文档」技能（[office.ts](src/agent/skills/office.ts)）用来新建或修改 Word、Excel、PowerPoint 文件，或把它们导出为 PDF，如「帮我做一个介绍公司产品的 PPT」「把销售表的表头加粗并加上底色」「根据这些数据画一个柱状图」「把报告导出成 PDF」。它没有内置的写入代码，而是由 LLM 写一段代码，经你同意后运行（工具 `run_office_script`）：

| 方式 | 说明 |
| --- | --- |
| **Microsoft Office**（优先） | 用 PowerShell 通过 COM 调用本机的 Word、Excel、PowerPoint。Office 能做的都能做：任意格式、图表、目录、公式计算、导出 PDF，并且原样保留文件中的其他内容 |
| **Python 库**（其次） | 对应的 Office 程序没有安装时，使用 python-docx、openpyxl、python-pptx（`pip install python-docx openpyxl python-pptx`）。openpyxl 不计算公式，打开已有文件再保存可能丢失其中的图片与图表 |

技能会检测本机装了哪些 Office 程序与 Python 库（可以在设置面板的 **Tools → Office 文档** 中查看与重新检测），写进使用说明，并只附上能用的示例代码（[office-examples/](src/agent/skills/office-examples/)）。

- **运行前**：检查 `files` 中列出的文件——必须在授权的文件夹中；正在 Office 中打开着的文件会提示先关闭（否则脚本会卡住或写入失败）。授权卡片列出要修改与新建的文件、调用方式与完整代码，每次都需要确认。同意后备份要修改的文件。
- **运行后**：对比每个文件的内容，把改动（修改、新建，甚至被删除）记录到 **Tools → 文件操作记录**，可以一键撤销；再读取改动后的文件内容交给 LLM 确认结果，不符合要求时可以修改代码再运行一次（会再次请求同意）。
- **调用 Office 的注意事项**（已写进使用说明与示例代码）：
  - 设置 `DisplayAlerts`，否则弹出的对话框会让脚本卡住；设置 `AutomationSecurity = 3`，禁止运行文档中的宏。
  - 出错时不保存；只在没有其他文档打开时退出 Office——PowerPoint 只有一个实例，可能正是你在用的那个。
  - 传给 Office 方法的值必须是普通的字符串或数字：`Join-Path` 等命令的输出直接传给 Office 会让它卡住，需要先转换；在循环中给同一个属性交替赋文字和数字会出错，Excel 写入多个单元格时用二维数组一次写入。
  - Word 的内置样式用编号，因为中文版 Office 的样式名是中文。
- **残留的 Office 进程**：通过 COM 启动的 Office 不是脚本的子进程，脚本出错或超时被结束时，Office 会残留在后台并一直占用文件。运行前会记下已有的 Office 进程，运行后结束新出现的、没有可见窗口的 Office 进程，不会影响你自己打开的 Office。
- **错误输出**：PowerShell 以 `-EncodedCommand` 运行时错误输出是 CLIXML，会还原为普通文字再交给 LLM。
- **验证**：示例代码在 Rust 端的测试（[office_tests.rs](src-tauri/src/files/office_tests.rs)）中用真实的 Office 与 Python 库运行，并读回生成的文件检查内容。这些测试需要安装 Office，默认跳过，手动运行：`cargo test --lib office_tests -- --ignored --test-threads=1`。

### 新增技能

在 [src/agent/skills/](src/agent/skills/) 下实现一个 `Skill`，并在 [skills/index.ts](src/agent/skills/index.ts) 中注册：

```ts
import { tool } from 'ai'
import { z } from 'zod'

export const mySkill: Skill = {
  id: 'my_skill',                       // 意图识别阶段输出的 id
  name: '我的技能',                      // 界面展示名
  description: '这个技能能处理哪些请求',    // 意图识别依据，越具体越好
  examples: ['用户可能会怎么说'],
  instructions: '技能被激活后，告诉 LLM 如何使用这些工具',
  tools: {
    do_something: tool({
      description: '工具的作用',
      inputSchema: z.object({ text: z.string().describe('参数说明') }),
      execute: async ({ text }) => ({ result: text }), // 抛出的错误会被记录并告知 LLM
    }),
  },
}
```

工具名在所有技能之间需唯一。另外：

- **在工具中调用 LLM**：`getSkillContext(options)`（`execute` 的第二个参数）可以拿到当前使用的模型 `model` 与识图模型 `visionModel`，参考 [selection.ts](src/agent/skills/selection.ts)、[image.ts](src/agent/skills/image.ts)。
- **结果卡片**：返回值中带上 `display: { title, content, format? }`，结果会以卡片形式完整展示在回复下方，角色只需简短点评，适合译文、总结这类需要原样呈现的长文本。
- **直接调用**：`useChatStore().sendMessage(文字, { directCall: { skillId, toolName, input } })` 跳过意图识别直接执行工具，可同时用 `quote` 附带一段引用文字。
- **请求授权**：涉及隐私或副作用的操作，在工具中调用 `getSkillContext(options).requestPermission({ kind, title, reason, target })`，对话中会弹出授权卡片，返回用户是否允许；同一 `kind` 选择「始终允许」后不再询问，传入 `allowAlways: false` 则每次都需要确认（如移动文件）。另外 `attachImages` 可以把工具产生的图片附加到用户消息上，`setStatus` 可以更新界面上的进度。参考 [screen.ts](src/agent/skills/screen.ts)、[files.ts](src/agent/skills/files.ts)。
- **动态说明**：`instructions` 也可以是返回字符串的函数，每次激活技能时重新生成，例如「本地文件」技能会在说明中列出当前授权的文件夹。
- **主动说话**：需要让桌宠主动开口时（如定时任务完成），调用 `useChatStore().speakProactively('事件描述')`。

## 长期记忆

每次回复前（[src/memory/](src/memory/)、[src-tauri/src/memory/](src-tauri/src/memory/)）：

1. **构造查询**：以最新的用户消息为主，附带上一轮对话作为上下文（便于理解「那明天呢」这类省略）。
2. **生成查询向量**：配置了向量模型时调用 embedding 接口；超时（5 秒）或出错时退化为只按关键词匹配，不影响对话。
3. **综合排名**（Rust 端，[rank.rs](src-tauri/src/memory/rank.rs)）：
   - **相关性**：有向量时，语义相似度占 75%、关键词匹配占 25%；没有向量时只看关键词匹配。语义相似度按全部记忆的分布归一化（不同向量模型的余弦相似度分布差别很大）；关键词匹配中文按相邻两字切分，并按逆文档频率加权。相关性低于门槛的记忆不参与排名，避免「很重要但与话题无关」的记忆被塞进 Prompt。
   - **重要程度**：0 ~ 1，写入记忆时给出。
   - **新近程度**：按类别的半衰期指数衰减。
   - **综合得分** = 相关性 × 0.6 + 重要程度 × 0.25 + 新近程度 × 0.15，权重可在设置中调整；默认召回前 6 条。
   - **核心档案**：重要程度 ≥ 0.8 的用户档案（如名字）每次都会带上，最多 5 条，不参与排名。
4. **写入 Prompt**：按类别分组附加在人设提示词之后（总字数约 1500 字以内），并提示 LLM 自然地运用、与用户最新说法冲突时以用户为准。召回的记忆同时提供给工具执行阶段，用于推断用户没有明说的参数（如问天气时的所在城市）。记忆检索与意图识别并行进行。
5. 回复下方会显示「想起了 N 件事」，点开可以看到这次用到了哪些记忆。

| 类别 | 内容 | 新近程度半衰期 |
| --- | --- | --- |
| 用户档案 `profile` | 姓名、职业、居住地等相对稳定的个人信息 | 不衰减 |
| 偏好习惯 `preference` | 喜好、厌恶、习惯、作息 | 180 天 |
| 关系印象 `relationship` | 对用户的整体印象、彼此关系的变化 | 90 天 |
| 计划约定 `plan` | 用户的计划、目标，以及与桌宠的约定 | 21 天（计划时间未到时不衰减） |
| 情景记忆 `episodic` | 与用户之间发生过的具体事件 | 30 天 |

### 记忆写入

每轮对话结束后，在后台整理这一轮的记忆（[src/memory/writer.ts](src/memory/writer.ts)），不阻塞下一轮对话：

1. **提取**（[extract.ts](src/memory/extract.ts)）：LLM 阅读最新一轮对话（附带之前几条作为上下文），提取关于用户的、值得长期记住的信息，给出类别、重要程度（0 ~ 1），情景记忆与计划约定还会把「明天」「下周三」换算成具体时间。闲聊、知识问答、翻译的文字、查询结果等不会被记住；大多数对话没有需要记住的信息，此时到此为止。消息太短（如「嗯」）或是划词 / 截图工具栏上的一次性操作时不整理。
2. **查找相似记忆**：为新记忆生成向量，在记忆库中找出最相似的 5 条已有记忆。
3. **去重、合并**（[merge.ts](src/memory/merge.ts)）：
   - 与某条已有记忆内容完全相同（忽略标点、空白与开头的「用户」）：视为 **再次提到**，刷新这条记忆的更新时间，重要程度只升不降，不调用 LLM。
   - 记忆库中没有相似的记忆：直接 **新增**，不调用 LLM。
   - 其余情况由 LLM 判断：**新增**、**重复**（再次提到），或 **更新**——新信息补充、修正或推翻了已有记忆（如搬家、换工作、喜好改变）时，改写为一条合并后的最新记忆，必要时保留「以前……」这样的历史；被合并后的记忆完全包含的其他记忆会被 **归档**。LLM 只能引用提供给它的记忆 id，不合法的决定一律按新增处理。
4. **写入**：新增与合并后的内容会生成向量；生成失败时照常写入，之后在后台补全。

回复下方会显示「记住了 N 件事」，点开可以看到新增与更新的记忆（更新的记忆会显示原来的内容）。每轮对话会多一次模型调用（提取），有新信息且记忆库中有相似记忆时再多一次（合并），可以在设置中关闭「自动记忆」。

所有记忆变动（新增、更新、再次提到、归档、恢复、删除）都会连同变动前的状态记录在数据库的 `memory_events` 表中（保留最近 2000 条），可以撤销，见下文「记忆管理」。

### 记忆管理

- **编辑**：在设置面板的记忆库中修改内容、类别、重要程度、发生时间。**固定** 的记忆不会被自动整理或遗忘。修改内容后会重新生成向量。
- **撤销**：同一次操作产生的变动属于同一批——一轮对话后的整理、一次记忆整理、一次遗忘、一次手动编辑——在「最近的变动」中整批撤销：新增的会被删除，修改与合并会恢复原状，归档的会恢复，删除的会按原来的 id 重新插入。某条记忆之后又被修改过时，需要先撤销之后的变动。回复下方「记住了 N 件事」展开后也可以直接撤销这一轮的记忆变动。
- **整理**（[consolidate.ts](src/memory/consolidate.ts)）：Rust 端把记忆按类别分组（有向量时按「最近邻链」排序，让相似的记忆落在同一组，每组最多 40 条），逐组交给对话模型：合并重复与矛盾的记忆、把多次出现的情景归纳为习惯、改写含糊的表述、归档已失效的记忆。合并时保留其中最重要的一条并改写内容，其余归档。LLM 只能引用本组的记忆 id，每条记忆最多参与一个操作，不合法的操作会被丢弃。**自动整理**每天最多一次，且自上次整理后至少有 20 条新增或修改的记忆时才进行；也可以在设置中立即整理。
- **遗忘**（[maintain.rs](src-tauri/src/memory/maintain.rs)）：按艾宾浩斯遗忘曲线计算 **记忆强度** R = e^(−t / S)，t 为距离最近一次巩固（写入、更新、被想起）的天数，稳定性 S = 30 天 × (1 + 4 × 重要程度) × (1 + ln(1 + 被想起次数))——越重要、越常被想起的记忆忘得越慢，每次被想起都会重新巩固；已经过去的计划从计划时间开始淡忘。**自动遗忘** 每天检查一次，把记忆强度低于 15%、重要程度低于 0.6 的记忆归档；核心档案、固定的记忆与 7 天内的新记忆不会被遗忘。被遗忘的记忆可以在「已归档」中恢复，也可以撤销整次遗忘。例如重要程度 0.3、从未被想起的记忆约 4 个月后被遗忘。
- **对话中管理**：「记忆管理」技能可以回答「你都记得我哪些事」，也可以按用户要求忘掉某些记忆：先查找相关记忆，再弹出授权卡片列出要忘掉的内容，用户确认后归档（可以撤销）。使用这个技能的一轮对话不会进行记忆写入，避免刚忘掉的事又被记回去。

### 配置与管理

设置面板的 **Memory** 页：

- **向量模型**：选择一个 OpenAI 兼容或 Gemini 协议的 Provider 并填写 embedding 模型，如 `text-embedding-3-small`、`bge-m3`（硅基流动）、`text-embedding-v3`（阿里云百炼）。未配置时只按关键词匹配。更换模型后会在后台为已有的记忆重新生成向量（只有同一模型生成的向量才会互相比较）。
- **检索测试**：输入一句话，查看会召回哪些记忆及各项得分，便于调整权重。
- **自动记忆**：开启后每轮对话后自动整理记忆（默认开启）。
- **记忆库**：按类别查看、手动添加、编辑、固定与删除记忆，显示每条记忆的记忆强度；「已归档」中可以恢复或永久删除被合并、遗忘的记忆。
- **整理与遗忘**：自动整理、自动遗忘的开关（默认开启），立即整理、预览与立即遗忘，以及撤销上一次整理或遗忘。
- **最近的变动**：按批次列出最近的记忆变动，包括来源（对话 / 手动 / 整理 / 遗忘）与修改前的内容，可以整批撤销。

数据库文件为应用数据目录下的 `memory.db`（Windows 上一般是 `%APPDATA%\com.tauri.dev\memory.db`，设置页中会显示完整路径），只在桌面应用中可用。记忆通常在数千条以内，向量以 BLOB 存储，检索时逐条计算余弦相似度即可，不需要向量数据库。

## 工作流程

```
用户输入
  → ChatStore
  → 长期记忆：检索相关记忆（与意图识别并行）
  → Agent：意图识别 → 工具执行（需要技能时）
  → LLM 以角色口吻流式输出
  → 长期记忆：在后台提取这一轮值得记住的信息，去重、合并后写入；每天按需整理与遗忘
  → 文本处理队列：解析 <情绪> 标签，按句末标点切分句子
  → 语音合成队列：逐句调用 TTS
  → 播放队列：按原始顺序播放音频 / 切换表情与动作
  → Live2D 模型：口型同步 + 表情动作
```

## 注意事项

- API Key 等设置、待办与文件操作记录仅保存在本地（WebView / 浏览器的 `localStorage`，对话中的图片保存在 IndexedDB，长期记忆保存在 SQLite）中，并由前端直接请求各服务商接口。桌面应用与浏览器中的设置互不相通。
- 「运行脚本」技能运行的脚本拥有与你相同的权限，可以读写、删除任何文件；请在授权卡片中确认脚本内容可信后再允许。
- 被阅读的文件、网页内容、脚本的输出与截图会发送给对话模型或识图模型的服务商，搜索词会发送给所选的搜索服务。
- 打包前需要将 [tauri.conf.json](src-tauri/tauri.conf.json) 中的 `identifier` 改为唯一的值（默认的 `com.tauri.dev` 无法用于打包）。修改后 WebView 的数据目录随之改变，之前保存的设置需要重新填写。
- 目前窗口只覆盖一块显示器。
- 仓库内置的 ATRI 模型及语音素材版权归原作者所有，仅供学习交流使用。
